# 조직보드 개발 계획 — Epic · Story

- 버전: v0.9
- 작성일: 2026-09-15
- 상태: 개발 진행 중 · S00.01 완료 (2026-09-15)
- 기준 문서: [PRD v1.0](prd.md), [FRD v0.9](frd.md), [TRD v0.9](trd.md)
- 계획 규모: **9개 Epic / 30개 Story / FRD 필수 기능 68개**
- 목표: Windows localhost에서 직원정보와 사진을 처리해 25 × 38mm 카드가 배치된 A4 가로 PDF를 생성하는 MVP를 완성한다.

## 1. 계획의 전제

Epic은 함께 완성할 큰 기능 묶음이고, Story는 개별 구현·검증·완료 판정이 가능한 작업 단위다. 기술 시험 Story는 실험 코드와 검증 기록을 산출물로 삼는다.

계획 작성 당시에는 문서만 있었으며 모든 Story는 미착수였다. 현재 진행 상태는 §8과 [검증 기록](verification.md)을 따른다. 개발 착수는 기존 FRD·TRD의 승인·실증 상태를 자동으로 변경하지 않는다. 정해진 출시일이 없으므로 달력 일정 대신 선행 조건과 마일스톤을 기준으로 계획한다. 규모 S/M/L은 상대적인 작업량이며 소요일수나 확정 견적이 아니다.

- **S:** 범위가 좁고 한 모듈에서 검증 가능한 작업.
- **M:** 여러 상태 또는 모듈을 연결하는 작업.
- **L:** Worker·이미지·PDF·실행 환경처럼 기술 불확실성이나 통합 검증이 큰 작업. 착수 시 내부 태스크를 나누되 Story ID와 완료 기준은 유지한다.

모든 Story는 MVP 또는 그 검증에 필요하다. 순서가 뒤라는 이유로 선택 기능이 되지 않는다. 로그인, DB, 자동 저장, 외부 배포, 얼굴 신원 식별, 배경 제거와 개별 이미지 다운로드는 포함하지 않는다. API·DB 개발 Epic도 만들지 않는다.

## 3. Story 상세

각 Story의 체크박스는 공통 완료 기준(§6)까지 충족했을 때만 체크한다. `선행: 없음`인 S00.01이 첫 실행 작업이다. 별도 언급이 없는 구현·자동 검증 담당은 개발자이며, 실제 PC·프린터 확인과 업무 시안 판단은 사용자와 함께 수행한다.

### E00. 기술 시험과 디자인·실행 기준 확정

**Epic 완료:** 실제 시험 결과로 권장 스택·치수·성능 상한을 판단하고, 제품 구현에 필요한 화면과 정책의 모호함을 해소한다.

### E01. 세션 상태와 네 단계 공통 흐름

**Epic 완료:** 데이터를 현재 세션에서 유지하며 잘못된 단계 진행과 오래된 비동기 결과 적용을 방지한다.

#### [ ] S01.01 — 세션 모델과 자산 메모리 저장소

- 유형·규모: 기술 기반 / M · 선행: S00.06
- 목적: 직원 이름이 같아도 데이터와 사진을 ID로 구분하고 안전하게 변경한다.
- 작업: Employee·Photo·Link·Edit·Session, UUID, reducer, 자산 저장소, revision·epoch, 파생 상태를 구현한다. 브라우저 영구 저장·서버 API·DB는 사용하지 않는다.
- 완료 기준: 링크의 일대일 제약, 삭제 후 입력 순서 유지, 재연결 시 편집 폐기, 변경 항목별 무효화가 동작한다. 사진 버퍼는 상태 객체에 Base64로 복제되지 않는다.
- 검증·산출물: **T02·T12 기반**, 상태 전이·오래된 응답 폐기 단위 테스트, `domain/`, `state/`.

#### [ ] S01.02 — 네 단계 화면 틀과 진행 조건

- 유형·규모: 사용자 기능 / M · 선행: S01.01
- 목적: 사용자가 현재 단계와 해결해야 할 문제를 알고 이전 단계로 돌아갈 수 있다.
- 작업: 단계 표시, `getBlockingIssues` 계약, 이전·다음 이동, 요약 수치, 빈 화면과 첫 행동 버튼을 구현한다. 기능 모듈은 후속 Story에서 실제 연결한다.
- 완료 기준: 미입력·미매칭·처리 중·미확인 경고 등 상태 fixture에 따라 이동이 차단되고 수정 위치가 표시된다. 이전 이동은 값을 유지하며 요약은 상태 중복으로 인원을 부풀리지 않는다.
- 검증·산출물: **T02**, 모든 단계 전이 UI 테스트, 공통 shell·guard·selector. 실제 전체 흐름 검증은 S06.03·S08.01에서 수행한다.

- 목적: 사용자가 데이터 소실과 오류의 복구 방법을 알 수 있다.

- 완료 기준: 초기화 취소 시 유지·확인 시 상태와 자산 제거, 종료 경고 미지원 시 상시 안내가 있다. 오류에는 행·목록 위치와 다음 행동을 표시하고 이름 전체·사진·전체 파일 경로를 남기지 않는다.
- 검증·산출물: **T02·T12**, 확인창·키보드·로그 검사. 실제 Worker 정리는 S07.02에서 통합 확인한다.

### E02. 직원 직접 입력과 XLSX 가져오기

**Epic 완료:** 입력 순서를 지키며 직원정보를 생성하고, 오류 행만 수정해 다음 단계로 진행한다.

#### [ ] S02.01 — 직원 추가·수정·삭제와 허용값 검사

- 작업: 목록·행 편집·삭제 확인, 공백 정리, 허용 목록 검사, 동명이인 표시, 이름·직군 변경 시 재계산 이벤트를 구현한다.

- 검증·산출물: **T03**, CRUD·검증·순서·이벤트 테스트, 직원정보 화면.

#### [ ] S02.02 — XLSX 양식 다운로드와 Worker 파싱

- 유형·규모: 사용자 기능 / M · 선행: S02.01

- 작업: 헤더만 있는 입력 시트와 가상 예시 안내 시트 생성, 확정된 파서·압축 검사·시간 제한·행 결과 계약을 제품에 적용한다.

- 검증·산출물: **T04**, 양식 재입력·시트 선택·손상·시간 초과 테스트, SpreadsheetAdapter·Worker.

#### [ ] S02.03 — 가져오기 결과 수정·제외·재시도

- 유형·규모: 사용자 기능 / M · 선행: S02.02
- 목적: 담당자가 정상 행을 보존하면서 오류 행만 해결한다.

- 완료 기준: 수정한 행이 원래 가져오기 순서에 반영되고 미해결 오류는 진행을 막는다. 재시도는 기존 정상 행을 중복 추가하지 않으며 동명이인을 이름 기준으로 병합하지 않는다.
- 검증·산출물: **T04**, 혼합 입력·재시도·다중 배치·동명이인 통합 테스트. **M1 시연**.

### E03. 사진 검사와 안전한 일대일 매칭

**Epic 완료:** 잘못된 사람에게 사진을 자동 확정하지 않으며 남는 사진·미매칭 직원을 명확히 해결한다.

#### [ ] S03.01 — 사진 다중 업로드와 방향 정규화

- 유형·규모: 사용자 기능 / M · 선행: S02.03
- 목적: 담당자가 형식과 방향이 다른 사진을 한꺼번에 불러온다.
- 작업: 선택·드롭 입력, 시그니처·디코딩·용량·치수 검사, EXIF 어댑터, 썸네일·편집 사본과 원본 참조를 연결한다.
- 완료 기준: 정상 JPG·JPEG·PNG를 유지하고 실패 파일만 안내한다. EXIF 1~8을 한 번만 적용하고 원본 비율을 유지한다. 투명 PNG는 출력용 흰색 합성 정책을 따른다.
- 검증·산출물: **T05·T07 방향 검사**, 정상·손상 혼합과 크기 한계 fixture, 업로드 화면·이미지 어댑터.

#### [ ] S03.02 — 고유 이름 자동 매칭과 충돌 재검사

- 유형·규모: 사용자 기능 / M · 선행: S03.01
- 목적: 유일하게 일치하는 이름만 자동 연결한다.
- 작업: NFC·공백·영문 대소문자 정규화, 마지막 확장자 제거, 전체 묶음 검사 후 고유 키 매칭, 입력·사진 추가·이름 수정 후 재검사를 구현한다.
- 완료 기준: 직원·사진이 각각 하나일 때만 연결하고 숫자·괄호·기호를 삭제하지 않는다. 뒤늦게 중복이 생기면 자동 연결을 재검토하고 수동 연결은 유지한다. 편집 손실이 있는 변경은 영향 확인을 제공한다.
- 검증·산출물: **T06**, NFC/NFD·대소문자·중복·도착 순서·이름 변경 회귀 테스트, matcher.

#### [ ] S03.03 — 수동 연결·교체·해제와 매칭 완료

- 유형·규모: 사용자 기능 / M · 선행: S03.02
- 목적: 담당자가 동명이인·파일명 불일치를 해결하고 모든 직원의 사진을 확정한다.
- 작업: 미매칭 직원·사진 목록, 연결 교체 확인, 원자적 링크 변경, 남는 사진 삭제·무시, 연결·미매칭 수를 제공한다.
- 완료 기준: 한 사진을 두 직원에게 배정할 수 없다. 해제·재연결 시 편집 상태를 폐기하고 원본을 잘못 삭제하지 않는다. 모든 직원 연결 및 남는 사진 확인 후 편집 단계가 열린다.
- 검증·산출물: **T06**, 교체 충돌·삭제·무시 취소·완료 조건 UI 테스트. **M2 시연**.

### E04. 얼굴 자동 크롭과 수동 편집

**Epic 완료:** 자동 처리 실패를 사용자가 복구하고 수정 결과가 직원 이동·화면 크기 변화에도 유지된다.

#### [ ] S04.01 — 얼굴 검출 Worker와 자동 크롭

- 유형·규모: 사용자 기능 / L · 선행: S03.03
- 목적: 연결된 사진을 얼굴 위치에 맞춰 자동 배치하고 필요한 사진만 확인한다.

- 유형·규모: 사용자 기능 / L · 선행: S04.01
- 목적: 담당자가 인쇄 사진 영역을 보며 구도를 정밀하게 조정한다.

- 검증·산출물: **T08**, 경계·마우스·키보드·복원 테스트와 기준 격자 비교, 편집기.

#### [ ] S04.03 — 직원별 편집 상태와 경고 확인

- 유형·규모: 사용자 기능 / M · 선행: S04.02

- 검증·산출물: **T08**, 경고 확인·무효화·직원 전환 통합 테스트. 해상도 판정의 실제 연결은 S05.03에서 완료한다.

## 6. 공통 착수·완료·상태 관리

### 6.1 착수 조건

- 선행 Story가 완료되고 해당 Story가 의존하는 디자인·기술 결정이 기록되어 있다.
- 수정 대상과 검증 fixture를 확인했으며 실제 직원 개인정보를 테스트에 사용하지 않는다.
- Story가 L 규모이면 내부 구현 태스크와 검증 태스크를 나누고 이번 작업 범위를 기록한다.

### 6.2 완료 기준

- Story의 모든 완료 기준을 통과하고 연결된 FRD 기능의 정상·예외 동작을 확인한다.
- 변경에 맞는 타입 검사·린트·테스트·빌드를 수행한다. UI 변경은 실제 브라우저에서 확인하며 수동 검증은 환경과 결과를 남긴다.
- 실패 경로가 정상 데이터 손실·잘못된 연결·이전 결과 덮어쓰기를 일으키지 않는다.
- 요구사항과 실제 구현이 달라졌다면 이유와 영향을 FRD·TRD·계획에 반영한다. 잠정값을 근거 없이 확정으로 바꾸지 않는다.
- 검증 명령·결과·산출물과 코드 변경 식별자를 기록한다. Git 준비 이후 Story 단위로 커밋하고 관련 없는 변경은 섞지 않는다.
- 진행 상태를 완료로 바꾸고 체크박스를 체크한다. 시험 코드 존재나 일부 테스트 통과만으로 완료하지 않는다.
