# 조직보드 사진 제작 자동화 웹페이지 기능정의서

상태: 작성 완료 · 사용자 최종 확인 대기

- 문서 버전: v0.9
- 작성일: 2026-09-15
- 기준 문서: `doc/prd.md` v1.0
- 작성 목적: 사용자가 무엇을 입력하고 어떤 버튼을 누르면 시스템이 무엇을 처리하며, 화면에 어떤 결과와 오류를 보여줘야 하는지 기능 단위로 정의한다.

> FRD는 화면과 기능의 행동 약속이다. 라이브러리 선정, 폴더 구조와 세부 계산식은 이후 `doc/trd.md`에서 확정한다.

## ⓪ 먼저 보는 범위 요약

- 필수 하위 기능: 68개
- 사용자 화면: 직원정보 입력, 사진 업로드·매칭, 사진 편집, 인쇄 미리보기·PDF의 네 화면
- 실행 방식: 한 명이 Windows PC에서 `localhost`로 사용하는 로컬 웹앱
- 데이터 방식: XLSX와 사진을 작업할 때마다 불러오며 별도 데이터베이스를 사용하지 않음
- 개인정보 원칙: 사진과 직원정보를 외부 서버나 외부 AI로 전송하지 않음
- 최종 결과: 사진세트가 정확히 25 × 38mm인 A4 가로 PDF
- 페이지 배치: 7열 × 3행, 페이지당 최대 21명
- 예상 개발 규모: 중간 이상
- 우선 검증 항목: 얼굴 자동 배치 품질, 편집 좌표 일치, Nanum Gothic 포함, 실제 인쇄 크기

### 범위를 줄여야 할 때의 원칙

사진 매칭, 수동 보정과 정확한 PDF 출력은 제품의 핵심이므로 제외하지 않는다. 일정이 부족하면 다음 항목만 순서대로 단순화한다.

1. 키보드 방향키를 이용한 미세 이동
2. 문제가 있는 항목만 모아 보는 필터
3. 인터넷 연결 없이 실행하는 완전 오프라인 구성

데이터베이스, 로그인, 작업 저장, 여러 템플릿과 외부 배포는 이미 MVP 범위에서 제외되어 있다.

## ① 서비스 요약

사용자는 직원정보를 직접 입력하거나 XLSX로 불러온 뒤 여러 장의 사진을 업로드한다. 시스템은 사진 파일명과 이름을 비교해 자동으로 연결하고, 얼굴 위치를 기준으로 조직보드 사진 영역에 맞게 자동 편집한다. 사용자는 필요한 사진만 확대·축소·이동하여 보정한다. 시스템은 계약형태와 직군 규칙에 맞는 컬러칩과 이름을 적용하고, 사진세트를 A4 가로 페이지에 21명씩 배치해 PDF로 만든다.

### 이번에 확정한 기능 원칙

- 모든 사진 처리와 PDF 생성은 브라우저 안에서 수행한다.
- 파일명 자동 매칭은 신원 추정이 아니라 문자열 비교만 사용한다.
- 동명이인과 중복 사진은 자동 확정하지 않는다.
- 얼굴 검출은 자동 크롭의 시작점을 계산하는 데만 사용한다.
- 자동 결과가 적절하지 않아도 사용자가 직접 수정할 수 있다.
- 계약형태 전용색이 직군색보다 우선한다.
- 직원정보 입력 순서가 PDF 배치 순서가 된다.
- 미매칭 직원, 처리 중인 사진과 확인하지 않은 필수 경고가 남으면 PDF를 만들 수 없다.
- 저해상도 경고는 사용자가 확인한 뒤 출력할 수 있다.
- 기존 슬라이드의 85% 인쇄 대신 신규 PDF를 실제 크기 100%로 출력한다.

## ② 전체 기능 목록

모든 기능은 MVP 필수 기능이다. 괄호 안은 사용자가 기능을 시작하는 화면이다.

### F1. 로컬 실행과 전체 작업 흐름 — 필수 6개

- **F1.1 로컬 앱 시작** — 사용자는 코드를 수정하지 않고 안내된 실행 방법 한 번으로 앱을 시작하고 브라우저의 `localhost` 화면을 연다. 앱이 준비되지 않으면 원인과 다시 실행하는 방법을 보여준다. (진입: 앱 실행)
- **F1.2 네 단계 작업 표시** — 화면 상단에 `1 직원정보 → 2 사진 매칭 → 3 사진 편집 → 4 PDF 출력` 단계를 현재 위치와 함께 표시한다. (진입: 모든 화면)
- **F1.3 다음 단계 진입 조건** — 현재 단계의 필수 입력이 없거나 해결해야 할 오류가 있으면 다음 단계로 이동하지 않고, 막힌 이유와 수정할 위치를 보여준다. (진입: 각 단계의 다음 버튼)
- **F1.4 이전 단계 이동과 상태 유지** — 이전 단계로 돌아가도 현재 브라우저 세션 안의 정상 입력, 사진 연결과 편집 값을 유지한다. 앞 단계의 값을 수정하면 뒤 단계 결과를 다시 계산한다. (진입: 이전 버튼 또는 단계 표시)
- **F1.5 작업 현황 요약** — 전체 직원, 사진 연결 완료, 미매칭, 자동 편집 완료, 확인 필요 수를 화면에서 확인할 수 있다. (진입: 직원정보 이후 모든 화면)
- **F1.6 현재 작업 초기화** — 사용자가 초기화를 선택하면 직원정보, 사진, 매칭, 편집과 미리보기가 모두 사라진다는 확인창을 보여주고, 다시 확인한 경우에만 현재 작업을 삭제한다. (진입: 공통 메뉴)

### F2. 직원정보 직접 입력과 XLSX 불러오기 — 필수 10개

- **F2.1 직원 직접 추가** — 이름, 직군과 계약형태를 입력해 직원 한 명을 목록에 추가한다. 이름은 공백만 입력할 수 없고 직군·계약형태는 허용 목록에서 선택한다. (진입: 직원정보 입력)
- **F2.2 직원 목록 보기** — 입력 순서대로 번호, 이름, 직군, 계약형태, 사진 연결 상태와 입력 오류를 표시한다. (진입: 직원정보 입력)
- **F2.3 직원 수정** — 이름, 직군과 계약형태를 수정한다. 이름이 바뀌면 자동 매칭 상태를 다시 점검하고, 직군·계약형태가 바뀌면 컬러칩을 즉시 다시 계산한다. (진입: 직원정보 입력)
- **F2.4 직원 삭제** — 삭제 대상의 이름과 연결된 사진이 함께 해제된다는 내용을 확인한 뒤 직원을 목록에서 제거한다. 삭제되지 않은 직원의 입력 순서는 유지한다. (진입: 직원정보 입력)
- **F2.5 입력값 정리** — 이름의 앞뒤 공백은 제거하고 내부의 연속 공백은 하나로 정리한다. 사용자가 입력한 한글·영문·일문 표기는 임의로 번역하거나 바꾸지 않는다. (진입: 직접 입력·수정·XLSX 불러오기)
- **F2.6 허용 직군 선택** — MVP 직군은 `디자인`, `서비스`, `개발`, `백오피스`, `QA`이다. 목록에 없는 직군은 오류로 표시한다. (진입: 직원정보 입력)
- **F2.7 허용 계약형태 선택** — MVP 계약형태는 `정규직`, `계약직`, `아르바이트`, `파견직`, `인턴`이다. 목록에 없는 계약형태는 오류로 표시한다. (진입: 직원정보 입력)
- **F2.8 XLSX 기본 양식 다운로드** — `이름`, `직군`, `계약형태` 열과 입력 예시가 포함된 빈 양식을 내려받을 수 있다. 실제 직원정보나 개인정보는 예시에 포함하지 않는다. (진입: 직원정보 입력)
- **F2.9 XLSX 불러오기** — `.xlsx` 파일의 첫 번째 표시 시트를 읽고 필수 열을 확인한 뒤 유효한 행을 직원 목록으로 가져온다. `.xls`, CSV와 다른 파일 형식은 읽지 않는다. (진입: 직원정보 입력)
- **F2.10 가져오기 결과와 순서** — 정상 행 수와 오류 행 수를 알려주고, 오류가 있는 행은 원본 XLSX 행 번호와 이유를 표시한다. 정상 행은 XLSX 순서를 유지하며, 동명이인은 허용하되 `동명이인` 상태로 표시한다. (진입: 직원정보 입력)

### F3. 사진 업로드와 이름 매칭 — 필수 10개

- **F3.1 사진 여러 장 선택** — JPG, JPEG 또는 PNG 사진을 한 번에 여러 장 선택하거나 업로드 영역에 끌어다 놓는다. (진입: 사진 업로드·매칭)
- **F3.2 사진 파일 검사** — 지원하지 않는 형식, 읽을 수 없는 파일과 이름이 없는 파일을 구분해 알려주고 정상 사진은 유지한다. 파일별 용량과 전체 권장 수량의 상한은 TRD에서 성능 검증 후 확정한다. (진입: 사진 업로드·매칭)
- **F3.3 매칭용 문자열 정리** — 사진 파일에서 마지막 확장자를 제거하고 Unicode NFC 정규화, 앞뒤 공백 제거와 연속 공백 정리를 수행한다. 영문 대소문자는 구분하지 않으며 괄호·숫자·기호를 임의로 제거하지 않는다. (진입: 자동 매칭)
- **F3.4 고유 이름 자동 매칭** — 정리된 파일명과 직원 이름이 정확히 같고 직원과 사진이 각각 한 개뿐이면 자동으로 연결한다. 예를 들어 `김현정.jpg`는 고유한 `김현정` 직원에게 연결한다. (진입: 사진 업로드·매칭)
- **F3.5 동명이인·중복 자동 확정 금지** — 같은 이름의 직원이 둘 이상이거나 같은 이름으로 판단되는 사진이 둘 이상이면 누구에게도 자동 확정하지 않고 `수동 연결 필요`로 표시한다. (진입: 자동 매칭)
- **F3.6 미매칭 직원과 사진 표시** — 사진이 없는 직원과 직원에게 연결되지 않은 사진을 별도 영역 또는 필터로 구분한다. (진입: 사진 업로드·매칭)
- **F3.7 사진 수동 연결** — 사용자가 직원 한 명과 미매칭 사진 한 장을 직접 선택해 연결한다. 연결 직전에 양쪽의 현재 상태를 확인하고 충돌이 없을 때 적용한다. (진입: 사진 업로드·매칭)
- **F3.8 연결 해제와 다시 연결** — 자동 또는 수동 연결을 해제해 사진과 직원을 다시 미매칭 상태로 돌리고 다른 항목과 연결할 수 있다. (진입: 사진 업로드·매칭)
- **F3.9 일대일 연결 보장** — 직원 한 명에는 사진 한 장, 사진 한 장에는 직원 한 명만 연결한다. 기존 연결과 충돌하면 자동으로 덮어쓰지 않고 교체 여부를 묻는다. (진입: 수동 연결)
- **F3.10 매칭 완료 조건** — 모든 직원이 사진 한 장과 연결되면 매칭 단계를 완료로 표시한다. 남는 사진은 삭제하거나 무시 대상으로 확인할 수 있지만 사진이 없는 직원이 남으면 PDF 단계까지 완료할 수 없다. (진입: 사진 업로드·매칭)

### F4. 얼굴 검출과 사진 자동 편집 — 필수 8개

- **F4.1 브라우저 내 얼굴 검출** — 연결된 사진을 외부로 보내지 않고 브라우저 안의 얼굴 검출 모델로 처리한다. 모델을 준비하지 못하면 자동 편집 실패를 알리고 수동 편집은 계속 사용할 수 있게 한다. (진입: 사진 연결 완료 후)
- **F4.2 단일 얼굴 자동 인식** — 얼굴이 한 명 감지되면 얼굴 경계와 눈 위치를 바탕으로 자동 크롭의 중심과 확대율을 계산한다. (진입: 자동 편집)
- **F4.3 기본 자동 크롭** — 사진 영역을 빈틈없이 채우면서 원본 비율을 유지하고, 얼굴과 어깨가 과도하게 잘리지 않는 초기 구도를 만든다. (진입: 자동 편집)
- **F4.4 초기 얼굴 배치값** — 첫 구현은 얼굴 경계 높이가 사진 영역 높이의 약 55%, 얼굴 중심이 가로 50%, 두 눈의 중간 높이가 위에서 약 38%에 오도록 계산한다. 수치는 샘플 테스트를 통해 TRD에서 조정할 수 있다. (진입: 자동 편집)
- **F4.5 얼굴 미탐지 처리** — 얼굴을 찾지 못하면 원본을 사진 영역 중앙에 맞춘 기본 `cover` 구도로 열고 `얼굴을 찾지 못했습니다. 직접 위치를 조정한 뒤 확인해주세요.`라고 표시한다. (진입: 자동 편집)
- **F4.6 여러 얼굴 처리** — 얼굴이 둘 이상 감지되면 신원을 추정하거나 얼굴을 임의 선택하지 않고 중앙 기본 구도로 열며 `얼굴이 여러 명 감지되었습니다. 사용할 인물이 맞도록 직접 조정해주세요.`라고 표시한다. (진입: 자동 편집)
- **F4.7 사진 방향과 비율 보정** — 사진의 회전 방향 정보를 반영해 올바른 방향으로 보여주고, 가로·세로 사진 모두 찌그러뜨리지 않는다. (진입: 사진 읽기·자동 편집)
- **F4.8 일괄 처리 진행과 재시도** — 여러 사진을 순서대로 또는 안전한 병렬 수로 처리하면서 완료 수와 남은 수를 표시한다. 한 사진의 실패가 다른 사진 처리를 중단시키지 않으며 실패한 사진만 다시 시도할 수 있다. (진입: 자동 편집)

### F5. 사진 수동 편집과 확인 — 필수 8개

- **F5.1 편집 대상 목록** — 직원 이름, 미리보기, 자동 편집·확인 필요·사용자 수정 완료 상태를 목록으로 보여준다. 확인이 필요한 사진만 모아 볼 수 있다. (진입: 사진 편집)
- **F5.2 실제 사진 영역 표시** — 편집 프레임은 최종 사진세트의 사진 영역과 같은 비율로 표시하며 프레임 밖 영역은 흐리거나 가려 최종 크롭 범위를 알 수 있게 한다. (진입: 사진 편집)
- **F5.3 드래그 이동** — 사진을 마우스로 끌어 상하좌우 위치를 조정한다. 이동 후에도 사진 영역 안에 빈 배경이 생기지 않도록 이동 범위를 제한한다. (진입: 사진 편집)
- **F5.4 확대·축소** — 슬라이더, 버튼 또는 마우스 휠로 사진을 확대·축소한다. 최소 확대율은 사진 영역을 완전히 채우는 값이며, 최대 확대율은 과도한 화질 저하를 막을 수 있도록 TRD에서 확정한다. (진입: 사진 편집)
- **F5.5 방향키 미세 이동** — 편집 프레임이 선택된 상태에서 방향키로 사진을 조금씩 이동한다. 키보드 사용이 어렵더라도 마우스 조작만으로 같은 작업을 완료할 수 있다. (진입: 사진 편집)
- **F5.6 자동 편집으로 초기화** — 수동 조정값을 지우고 해당 사진의 최근 자동 편집 결과로 돌아간다. 자동 검출에 실패했던 사진은 중앙 기본 구도로 돌아간다. (진입: 사진 편집)
- **F5.7 원본 기준으로 다시 시작** — 자동 편집값과 수동 조정값을 모두 제거하고 원본 사진을 중앙 기본 구도로 다시 연다. 원본 파일 자체는 변경하지 않는다. (진입: 사진 편집)
- **F5.8 확인 완료와 직원 이동** — 확인 필요 사진은 사용자가 `이 사진 사용`을 눌러야 완료된다. 이전·다음 직원으로 이동할 수 있고, 조정값은 이동 즉시 현재 세션에 반영한다. (진입: 사진 편집)

### F6. 컬러칩·이름·사진세트 생성 — 필수 8개

- **F6.1 컬러칩 우선순위 계산** — 계약형태에 전용색이 있으면 그 색을 사용하고, 전용색이 없으면 직군색을 사용한다. 사용자가 색상을 직접 고르는 기능은 MVP에 포함하지 않는다. (진입: 직원정보 입력·수정)
- **F6.2 직군 색상 적용** — 디자인 `#FFAE01`, 서비스 `#FF01A2`, 개발 `#0196FF`, 백오피스 `#47B50B`, QA `#9900FF`를 사용한다. (진입: 사진세트 생성)
- **F6.3 계약형태 색상 적용** — 계약직 `#E6B8AF`, 아르바이트 `#737373`, 파견직 `#A4C2F4`, 인턴 `#00FFFF`를 우선 사용하며 정규직은 직군색을 사용한다. (진입: 사진세트 생성)
- **F6.4 고정 크기 사진세트** — 사진, 컬러칩, 이름과 외곽선을 가로 25mm × 세로 38mm 안에 구성하고 인원수와 관계없이 크기를 유지한다. (진입: 사진세트 생성)
- **F6.5 내부 배치 규격** — 좌우 안쪽 여백 약 1.3mm, 상단 약 1.0mm, 사진·칩 너비 약 22.4mm, 사진 높이 약 26.3mm, 칩 높이 약 2.9mm, 이름 영역 약 9mm, 외곽선 약 0.6pt를 적용한다. (진입: 사진세트 생성)
- **F6.6 실시간 사진세트 미리보기** — 사진 위치, 확대율, 이름, 직군 또는 계약형태가 바뀌면 사진세트 미리보기를 즉시 갱신한다. (진입: 사진 편집·인쇄 미리보기)
- **F6.7 이름 표시와 긴 이름 처리** — Nanum Gothic 800, 가운데 정렬, 기본 12pt 한 줄로 표시한다. 들어가지 않으면 두 줄 10pt로 바꾸고, 그래도 들어가지 않으면 최소 9pt까지 줄인다. 9pt 두 줄에도 맞지 않으면 이름을 자르지 않고 PDF 생성을 막아 이름 수정을 요청한다. (진입: 사진세트 생성)
- **F6.8 저해상도 경고** — 최종 크롭에 사용되는 원본 픽셀이 300ppi 기준인 약 265 × 311px보다 작으면 `인쇄 시 사진이 흐릴 수 있습니다.`라고 경고한다. 사용자가 확인하면 출력은 허용한다. (진입: 사진 편집·인쇄 미리보기)

### F7. A4 페이지 미리보기와 PDF 생성 — 필수 10개

- **F7.1 A4 가로 페이지** — 페이지를 297 × 210mm 가로 방향으로 구성한다. 화면 미리보기는 축소해 보여도 PDF 내부 치수는 실제 mm 값을 유지한다. (진입: 인쇄 미리보기·PDF)
- **F7.2 7열 × 3행 배치** — 사진세트를 왼쪽에서 오른쪽, 위에서 아래로 7열 × 3행 배치한다. 사진세트 간 가로 간격은 약 2.2mm, 세로 간격은 약 1.0mm이다. (진입: 인쇄 미리보기·PDF)
- **F7.3 페이지 중앙 정렬** — 7열 전체 너비 약 188.2mm와 3행 전체 높이 약 116mm를 A4 페이지 중앙에 놓는다. 기본 좌우 여백은 약 54.4mm, 상하 여백은 약 47mm이다. (진입: 인쇄 미리보기·PDF)
- **F7.4 입력 순서와 페이지 나누기** — 직원정보 순서대로 배치하고 페이지당 최대 21명을 유지한다. 22번째 직원부터 같은 크기의 다음 페이지를 만든다. (진입: 인쇄 미리보기·PDF)
- **F7.5 마지막 페이지 빈자리** — 마지막 페이지에 21명보다 적은 인원이 있어도 앞에서부터 같은 위치에 배치하고 빈자리에는 카드, 테두리 또는 안내 문구를 그리지 않는다. (진입: 인쇄 미리보기·PDF)
- **F7.6 페이지별 미리보기** — 현재 페이지 번호와 전체 페이지 수를 표시하고 이전·다음 페이지를 볼 수 있다. 미리보기의 사진, 이름과 컬러칩은 PDF와 같은 데이터를 사용한다. (진입: 인쇄 미리보기·PDF)
- **F7.7 PDF 생성 조건 검사** — 직원이 없거나 미매칭 직원, 처리 중 사진, 이름 넘침과 확인하지 않은 필수 경고가 있으면 PDF 생성 버튼을 비활성화하고 해결할 항목을 보여준다. (진입: 인쇄 미리보기·PDF)
- **F7.8 브라우저 내 PDF 생성** — 직원정보와 사진을 서버에 보내지 않고 브라우저에서 PDF를 만든다. 생성 중에는 중복 실행을 막고 진행 상태를 표시하며 실패 시 입력과 편집 상태를 유지한다. (진입: PDF 생성 버튼)
- **F7.9 글꼴 포함과 파일명** — Nanum Gothic을 PDF에 포함하고 파일명을 `조직보드_YYYY-MM-DD.pdf` 형식으로 만든다. 파일명에 직원 이름을 포함하지 않는다. (진입: PDF 다운로드)
- **F7.10 인쇄 안내** — 다운로드 완료 후 `A4 가로`, `실제 크기 또는 100%`, `페이지에 맞춤·축소 해제`를 안내한다. 85% 축소 인쇄를 선택하지 않도록 명확히 표시한다. (진입: PDF 다운로드 완료)

### F8. 개인정보·세션·안정성 — 필수 8개

- **F8.1 메모리 안에서만 작업** — 직원정보, 원본 사진과 편집 상태를 현재 브라우저 세션 메모리에서만 사용하고 `localStorage`, IndexedDB 또는 데이터베이스에 영구 저장하지 않는다. (진입: 전체 작업)
- **F8.2 외부 전송 금지** — 직원정보, 사진, 크롭 이미지와 PDF를 외부 API, 분석 도구, 오류 수집 서비스 또는 외부 AI로 전송하지 않는다. (진입: 전체 작업)
- **F8.3 외부 데이터베이스 없음** — 직원정보와 작업결과를 저장하기 위한 서버 API나 데이터베이스를 만들지 않는다. 사용자는 원본 XLSX와 내려받은 PDF를 직접 보관한다. (진입: 전체 작업)
- **F8.4 새로고침·종료 경고** — 작업 데이터가 있는 상태에서 새로고침하거나 창을 닫으려 하면 저장되지 않은 작업이 사라질 수 있음을 경고한다. 브라우저가 경고를 지원하지 않는 경우 화면 안에도 같은 내용을 표시한다. (진입: 브라우저 새로고침·종료)
- **F8.5 메모리와 임시 URL 정리** — 사진을 삭제하거나 작업을 초기화하고 앱을 종료할 때 생성한 임시 이미지 URL과 대용량 메모리를 해제한다. (진입: 사진 삭제·작업 초기화·앱 종료)
- **F8.6 부분 실패 시 정상 항목 유지** — XLSX 한 행, 사진 한 장, 얼굴 검출 한 건 또는 PDF 생성이 실패해도 다른 정상 직원과 사진을 삭제하지 않는다. (진입: 오류 발생)
- **F8.7 개인정보 없는 오류 안내** — 개발 로그와 화면 오류에는 직원 사진의 내용, 직원 이름 전체와 사용자 PC의 전체 파일 경로를 남기지 않는다. 화면에는 사용자가 구분할 수 있는 행 번호나 목록 위치를 사용한다. (진입: 오류 발생)
- **F8.8 로컬 자산 사용** — 앱 실행에 필요한 얼굴 검출 모델, 글꼴과 핵심 정적 파일을 프로젝트 안에서 제공해 외부 CDN 장애나 인터넷 연결 여부가 핵심 기능에 영향을 주지 않도록 한다. (진입: 앱 시작)

## ③ 화면별 상태와 동작

### 3.1 직원정보 입력 화면

초기 상태:

- 직원이 없다는 설명과 `직원 추가`, `XLSX 불러오기`, `기본 양식 다운로드`를 보여준다.
- 사진 업로드 단계로 가기 전에 직원 한 명 이상이 필요함을 알려준다.

정상 상태:

- 직원 목록, 전체 인원과 동명이인 수를 표시한다.
- 행별 수정·삭제를 제공하고 목록 순서가 PDF 순서임을 표시한다.
- 유효한 직원이 한 명 이상이면 다음 단계로 갈 수 있다.

오류 상태:

- XLSX 오류는 원본 행 번호, 문제 열과 수정 방법을 표시한다.
- 정상 행은 유지하고 오류 행만 수정하거나 다시 불러올 수 있다.
- 허용되지 않은 직군·계약형태는 가장 가까운 값을 임의 선택하지 않는다.

### 3.2 사진 업로드 및 매칭 화면

초기 상태:

- 지원 형식과 `파일명은 직원 이름과 같게 준비하면 자동 연결됩니다.`라는 안내를 보여준다.
- 직원 목록은 사진 없음 상태로 표시한다.

처리 상태:

- 업로드 파일 수와 검사 진행 상태를 보여준다.
- 파일명 매칭은 빠르게 끝나더라도 결과 수를 요약한다.

정상 상태:

- 자동 연결, 수동 연결, 미매칭 직원, 남는 사진과 동명이인 상태를 구분한다.
- 사용자는 연결을 해제하거나 다시 연결할 수 있다.

완료 조건:

- 모든 직원에게 사진 한 장이 연결돼야 편집 단계를 완료할 수 있다.
- 남는 사진은 사용자가 무시 대상으로 확인하거나 목록에서 제거한다.

### 3.3 사진 편집 화면

초기 상태:

- 얼굴 검출 모델과 사진 처리 준비 상태를 보여준다.
- 처리 중에는 완료 수와 전체 수를 표시한다.

정상 상태:

- 왼쪽 또는 한쪽 영역에는 직원 목록과 상태, 중심 작업 영역에는 크롭 편집기, 옆에는 완성 사진세트 미리보기를 제공한다.
- 자동 편집이 정상인 사진은 바로 미리보기를 제공하고 사용자는 필요한 사진만 수정한다.

확인 필요 상태:

- 얼굴 미탐지, 다중 얼굴, 저해상도와 이름 넘침을 서로 다른 문구와 아이콘으로 표시한다.
- 얼굴 미탐지·다중 얼굴은 수동 조정 후 `이 사진 사용` 확인이 필요하다.
- 저해상도는 경고 내용을 확인한 뒤 계속 진행할 수 있다.
- 이름 넘침은 이름을 수정하기 전까지 PDF 생성이 불가능하다.

### 3.4 인쇄 미리보기 및 PDF 화면

초기 상태:

- 총 직원 수, 예상 페이지 수, 해결할 문제 수와 A4 출력 규격을 표시한다.

정상 상태:

- 페이지별 사진세트와 페이지 번호를 보여준다.
- 화면 확대·축소는 미리보기 보기에만 영향을 주며 PDF 실제 크기를 바꾸지 않는다.

생성 상태:

- PDF 생성 버튼을 잠그고 진행 상태를 표시한다.
- 성공하면 다운로드와 인쇄 설정 안내를 보여준다.
- 실패하면 오류와 다시 시도 버튼을 보여주고 작업 상태는 유지한다.

## ④ 대표 사용 장면

### 장면 1 — 직원 한 명을 직접 입력해 출력

1. 사용자가 이름, 직군과 계약형태를 입력한다.
2. 이름과 같은 파일명의 사진을 업로드한다.
3. 시스템이 사진을 자동 연결하고 얼굴 기준으로 배치한다.
4. 사용자가 결과를 확인하고 필요하면 위치를 조정한다.
5. 시스템이 컬러칩과 이름을 적용한다.
6. 사용자가 한 명이 배치된 A4 PDF를 내려받아 100%로 인쇄한다.

### 장면 2 — 직원 21명을 XLSX로 일괄 처리

1. 사용자가 XLSX와 사진 21장을 불러온다.
2. 시스템이 정상 행과 파일을 검사하고 고유 이름을 자동 연결한다.
3. 사용자가 미매칭 또는 확인 필요 항목만 수정한다.
4. 시스템이 한 페이지에 7열 × 3행으로 21명을 배치한다.
5. 사용자가 PDF를 내려받고 사진세트 크기를 확인한다.

### 장면 3 — 22명으로 두 페이지 생성

1. 직원정보 순서의 1~21번은 첫 페이지에 배치된다.
2. 22번째 직원은 두 번째 페이지의 첫 번째 자리에 같은 크기로 배치된다.
3. 두 번째 페이지의 나머지 빈자리에는 테두리나 빈 카드가 나타나지 않는다.

### 장면 4 — 동명이인과 파일명 불일치 처리

1. 시스템은 동명이인 사진을 자동 확정하지 않는다.
2. 사용자가 사진 미리보기와 직원 목록을 보고 직접 연결한다.
3. 파일명이 직원 이름과 다른 사진도 같은 방식으로 연결한다.
4. 일대일 연결이 완료되면 편집 단계로 이동한다.

### 장면 5 — 얼굴 검출 실패 사진 처리

1. 얼굴이 없거나 여러 명인 사진은 확인 필요로 표시된다.
2. 사용자가 사진을 직접 확대하고 위치를 맞춘다.
3. `이 사진 사용`을 눌러 해당 경고를 확인 완료한다.
4. 조정 결과가 사진세트와 PDF에 동일하게 반영된다.

## ⑤ 기능 정책과 결정 이유

### 5.1 자동 매칭은 보수적으로 처리한다

틀린 사람에게 사진을 연결하면 이름과 얼굴이 잘못 출력되는 큰 오류가 된다. 따라서 문자열이 정확하고 유일할 때만 자동 확정하며, 애매하면 사용자가 직접 연결한다.

### 5.2 자동 편집은 시작점이며 최종 판단은 사용자에게 둔다

얼굴 검출은 사진 구도, 안경, 조명, 가림과 배경에 따라 실패할 수 있다. 자동 결과를 강제로 사용하지 않고 모든 사진을 같은 편집기에서 수정할 수 있게 한다.

### 5.3 사진세트 전체 크기는 절대 줄이지 않는다

조직보드에 붙일 실제 크기가 중요하므로 인원수가 많아져도 카드나 간격을 축소하지 않는다. 페이지 수만 늘린다.

### 5.4 저해상도는 경고하되 사용자가 결정한다

오래된 사진이나 작은 사진밖에 없는 경우 업무를 완전히 막으면 사용할 수 없다. 예상 화질을 경고하고 사용자가 확인하면 PDF 생성을 허용한다.

### 5.5 이름은 숨기지 않는다

말줄임표나 임의 축약은 사람을 잘못 식별하게 할 수 있다. 정해진 최소 글자 크기와 두 줄에도 들어가지 않으면 사용자가 이름을 수정하도록 요청한다.

### 5.6 데이터는 저장하지 않는다

초기 사용자는 한 명이며 직원정보는 XLSX 원본으로 관리한다. 개인정보 위험과 구현 복잡도를 줄이기 위해 데이터베이스와 작업 저장을 두지 않는다.

## ⑥ 화면에는 보이지 않지만 필요한 기능

- 사진의 EXIF 회전 정보를 반영한 뒤 얼굴 검출과 크롭 좌표를 같은 기준으로 계산한다.
- 화면 미리보기와 PDF가 동일한 크롭 원본과 좌표를 사용하도록 하나의 편집 상태를 공유한다.
- 사진을 다시 연결하면 이전 사람의 편집값을 잘못 재사용하지 않는다.
- 직원 이름을 바꿨을 때 수동 연결은 유지하되 자동 연결이었음을 표시하고 충돌을 다시 검사한다.
- 얼굴 모델과 Nanum Gothic이 준비되기 전에 편집 또는 PDF 생성을 시작하지 않는다.
- 얼굴 검출이 화면 조작을 오래 막으면 Web Worker에서 처리한다.
- 대용량 사진은 화면용 미리보기와 PDF용 원본 처리를 구분하되 최종 화질을 임의로 낮추지 않는다.
- PDF 생성 중 새 작업이나 중복 생성을 막고 완료 또는 실패 후 다시 사용할 수 있게 한다.
- 브라우저 임시 URL, Canvas와 이미지 버퍼를 사용이 끝난 시점에 해제한다.
- 네트워크 요청 검증을 통해 직원정보와 사진이 외부로 전송되지 않는지 자동 테스트한다.

## ⑦ 모든 화면의 공통 동작 규칙

- 주요 버튼은 한 번 눌렀을 때 한 번만 실행된다.
- 처리 중인 버튼은 비활성화하고 현재 처리 내용을 짧은 한국어로 표시한다.
- 오류는 빨간색만으로 구분하지 않고 아이콘, 제목과 설명을 함께 사용한다.
- 오류 메시지에는 무엇이 문제인지와 사용자가 다음에 할 일을 함께 적는다.
- 팝업을 닫거나 이전 단계로 이동해도 정상적으로 입력된 값은 유지한다.
- 삭제, 연결 교체와 전체 초기화처럼 복구하기 어려운 작업은 실행 전에 대상을 다시 보여준다.
- 빈 화면에는 기능 설명과 첫 행동 버튼을 제공한다.
- 목록의 직원 이름과 사진 미리보기에는 구분 가능한 접근성 이름을 제공한다.
- 화면 확대·축소나 브라우저 배율이 PDF의 실제 mm 크기에 영향을 주지 않는다.
- 앱에는 직원정보나 사진을 외부로 보내지 않는다는 내용을 사용자가 확인할 수 있게 표시한다.

## ⑧ 사용자가 눈으로 확인할 완료 기준

### 직원정보

- 직원 한 명을 추가·수정·삭제할 수 있다.
- 기본 XLSX 양식을 내려받고 21명의 정보를 불러올 수 있다.
- 잘못된 XLSX 행은 행 번호와 이유가 보이며 정상 행은 유지된다.
- 동명이인은 오류로 삭제되지 않고 수동 매칭 대상으로 표시된다.

### 사진 매칭

- `김현정.jpg`가 고유한 `김현정` 직원에게 자동 연결된다.
- 동명이인과 사진 중복은 자동 확정되지 않는다.
- 사진을 직접 연결·해제·교체할 수 있다.
- 직원과 사진이 일대일로만 연결된다.

### 사진 편집

- 단일 정면 얼굴 사진이 기본 구도로 자동 배치된다.
- 사진을 마우스로 이동하고 확대·축소할 수 있다.
- 자동 편집 초기화와 원본 기준 초기화가 서로 구분되어 동작한다.
- 얼굴 미탐지·다중 얼굴 사진을 직접 수정하고 확인 완료할 수 있다.
- 편집 화면과 완성 사진세트의 크롭 결과가 같다.

### 사진세트와 PDF

- 직군과 계약형태에 맞는 정확한 컬러칩이 적용된다.
- 이름이 Nanum Gothic으로 표시되고 임의로 잘리지 않는다.
- 21명은 한 페이지, 22명은 두 페이지로 만들어진다.
- 모든 사진세트가 25 × 38mm이고 간격이 유지된다.
- PDF를 실제 크기 100%로 출력했을 때 목표 크기에서 ±0.5mm 안에 들어온다.
- 마지막 페이지의 빈자리에 불필요한 카드가 표시되지 않는다.

### 개인정보와 로컬 실행

- 안내된 한 번의 실행으로 `localhost` 화면을 열 수 있다.
- 직원정보, 사진과 PDF가 외부 서버로 전송되지 않는다.
- 데이터베이스 파일이 생성되지 않는다.
- 작업 중 새로고침하려 하면 데이터가 사라질 수 있음을 안내한다.
- 작업 초기화 후 사진과 직원정보가 화면과 메모리에서 제거된다.

## ⑨ 디자인·TRD에서 검증하거나 확정할 항목

다음 항목은 현재 기능 기본값을 유지하되 실제 시안과 기술 시험을 통해 확정한다.

- 얼굴 경계 높이 55%, 눈높이 38%가 실제 조직보드 사진에 적합한지
- 긴 이름의 12pt → 10pt → 9pt 규칙과 두 줄 높이가 읽기 좋은지
- 300ppi 기준 265 × 311px 미만 경고가 실사용에 적합한지
- 사진 한 장의 최대 용량과 한 작업의 권장 최대 사진 수
- 수동 편집 최대 확대율과 방향키 한 번의 이동량
- Windows에서 지원할 브라우저와 최소 버전
- XLSX를 브라우저에서 읽을 라이브러리
- MediaPipe 모델과 실행 파일을 프로젝트에 포함하는 방식
- 앱을 비개발자가 한 번에 시작·종료하는 방식
- Nanum Gothic 파일의 포함 범위와 PDF 용량
- 임원·기타 직군이 필요할 경우의 이름과 컬러값
