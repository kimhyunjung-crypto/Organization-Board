## 1. 개요 및 시험 목적

본 기술 시험(S00.04)은 화면(Canvas)과 인쇄용 PDF 간의 크롭 영역 일치(POC-03 완료), 로컬 Nanum Gothic ExtraBold 800 글꼴 및 긴 이름의 결정론적 줄바꿈·넘침 차단(POC-04), 그리고 A4 가로 7×3 그리드 25 × 38mm 카드 배치와 100mm 캘리브레이션 눈금자 치수 정밀도(POC-05)를 검증하고 독립적인 PDF 기하 검사를 통과하는 것을 목적으로 한다.

### 개인정보 및 보안 준수 원칙
- 실제 직원 개인정보(이름, 사진 등)는 일체 사용하지 않았으며, 전적으로 비식별 가상 성인 인물 합성 fixture(`tests/fixtures/images/synthetic-portrait.png`)만을 사용하였다.
- 외부 원격 CDN이나 Google Fonts 웹 폰트 요청 없이, 로컬 자산 `/assets/fonts/NanumGothic-ExtraBold.ttf`와 `@pdf-lib/fontkit`을 사용해 독립 임베딩을 수행하였다.

## 2. 모듈 구현 상세

### 2.1 소유 경로 및 파일 구조
- `src/technical/pdf/types.ts`: `JobCategory`, `ContractType`, `HexColor`, `RgbColor`, `CardRects`, `NameLayout`, `PagePosition`, `CardRenderPlan`, `DocumentRenderPlan` 등 인터페이스 정의
- `src/technical/pdf/constants.ts`: `PT_PER_MM = 72 / 25.4`, A4 가로(297 × 210mm), 카드(25 × 38mm), 0.6pt 외곽선, 0.3pt 인셋, 사진(22.4 × 26.3mm), 칩(22.4 × 2.9mm), 잠정 이름 영역(22.4 × 7.8mm, 실사용 7.4mm), 직군/계약 색상 상수
- `src/technical/pdf/colors.ts`: 계약형태 전용색 우선 적용 및 정규직 직군색 매핑 순수 함수 (`resolveChipColor`)
- `src/technical/pdf/fontLoader.ts`: `NanumGothic-ExtraBold.ttf` 바이너리 로더, `@pdf-lib/fontkit` 인스턴스화, 브라우저 Canvas용 `FontFace` 등록 (실패 시 차단 throw)
- `src/technical/pdf/nameLayout.ts`:
  - 12pt 한 줄 우선 검사
  - 초과 시 10pt → 9.5pt → 9.0pt 순차 검사 (최대 2줄)
  - 공백 우선 분할 후 불가 시 `Intl.Segmenter` 기반 grapheme 분할
  - `max(w1, w2)` 최소화하는 결정론적 Minimax 너비 분할 및 동률 시 선행 분할점 채택
  - 실제 글리프 잉크 바운딩 박스(`maxY`, `minY`) 반영 상하/좌우 정밀 중앙 정렬
  - 일본어/이모지 등 미지원 글리프 누락(`MISSING_GLYPH`), 빈 이름(`EMPTY_NAME`), 허용 초과(`NAME_OVERFLOW`) 차단
- `src/technical/pdf/renderPlan.ts`: Canvas와 PDF가 공통으로 소비하는 `CardRenderPlan` 및 `DocumentRenderPlan` 생성기 (0명 차단, 21명 1페이지, 22명 2페이지)
- `src/technical/pdf/canvasCardRenderer.ts`: `CardRenderPlan`을 300 ppi(295 × 449 px) Canvas에 렌더링하는 뷰어
- `src/technical/pdf/pdfGenerator.ts`: `pdf-lib` 기반 벡터 외곽선(0.6pt / 0.3pt 인셋), 벡터 칩, 벡터 텍스트, 래스터 사진 임베딩 및 100mm 캘리브레이션 눈금자/안내문 출력
- `src/technical/pdf/fixtures.ts`: 5개 직군 × 5개 계약형태 22인 합성 데이터셋 및 음성 테스트 텍스트
- `src/technical/pdf/PdfHarness.tsx`: 실시간 이름 레이아웃 판정기, 300 ppi 카드 Canvas 미리보기, 22인 캘리브레이션 시트 다운로더
- `scripts/generate-pdf-fixture.mjs`: 실제 모듈을 임포트하여 `output/pdf/org-board-print-calibration.pdf`를 브라우저 런타임에서 생성하고 PyMuPDF로 독립 검사하는 스크립트

## 3. 기술 시험(POC) 검증 결과

### 3.1 POC-03: Canvas와 PDF 크롭 좌표 일치
- **검증 내용:** 화면(Canvas) 카드 렌더링(`canvasCardRenderer.ts` / `renderCardPhoto`)과 PDF 생성(`pdfGenerator.ts`)이 동일한 `CardRenderPlan`의 `photoCrop: CropRect`를 소비.
- **결과:** 원본 이미지(1254 × 1254 px) 기준 크롭 사각형 `[x: 93, y: 0, width: 1068, height: 1254]`이 Canvas와 PDF에 정확히 동일하게 전달되어, 원본 좌표계 기준 오차 0px (1px 이내 합격 기준 충족).

### 3.2 POC-04: 글꼴·이름 배치 및 누락 글리프 차단
- **글꼴:** `NanumGothicExtraBold` (PostScript Name, UnitsPerEm: 1000, Ascent: 856, Descent: -144).
- **누락 글리프 차단:**
  - 일본어 한자/가나 샘플(`"田中 太郎"`): 글꼴 내 글리프 부재 감지 (`MISSING_GLYPH`), PDF 생성 차단 통과.
  - 미지원 이모지(`"홍길동 😊"`): 글리프 부재 감지 (`MISSING_GLYPH`), PDF 생성 차단 통과.
  - 공백/빈 문자열(`"   "`): `EMPTY_NAME` 차단 통과.
- **이름 배치 규칙 (TRD §9.3):**
  - `"홍길동"`, `"남궁민수"`, `"황보선생님"`: 12pt 1줄 배치 (폭 <= 63.50pt, 높이 <= 20.98pt).
  - `"김철수 연구원"` (공백 포함 초과): 공백 기준 2줄 분할 (`["김철수", "연구원"]`), 10pt 줄간격 1.05배 적용.
  - `"알렉산더피터슨"` (7자 무공백 초과): grapheme minimax 분할 (`["알렉산", "더피터슨"]`), 최대 줄 너비 37.60pt, 10pt 적용.
  - 초장문: 9pt 2줄 초과 시 말줄임표 없이 `NAME_OVERFLOW`로 안전 차단.
- **글리프 잉크 바운딩 박스 검증:**
  - 상단 돌출 글리프(`"훨"` 등, `maxY` = 885 > 856)에 대해 실제 잉크 상단과 하단이 이름 영역(30.4mm ~ 37.8mm) 내부로 정확히 클램프 및 중앙 정렬됨을 수학적으로 검증.

### 3.3 POC-05: 출력 치수 및 A4 7×3 그리드 배치 (독립 PDF 검사 통과)
`scripts/inspect-print-pdf.py`(PyMuPDF 1.28.0)를 실행하여 최종 생성된 `output/pdf/org-board-print-calibration.pdf`의 기하학적 치수를 직접 검사한 결과:
```json
{
  "pass": true,
  "errors": [],
  "pages": 2
}
```
- **페이지 규격:** Page 1 & Page 2 모두 정확한 A4 가로 (`297.00 × 210.00 mm`, 오차 < 0.003mm).
- **카드 외곽선:** Page 1에 21개, Page 2에 1개 카드가 감지됨. 외곽선은 0.6pt 두께이며, 외곽 물리 치수가 가로 25.00mm, 세로 38.00mm로 정확히 일치함.
- **슬롯 원점:**
  - Page 1 Slot 0 (54.40, 47.00 mm) ~ Slot 20 (217.60, 125.00 mm) 일치.
  - Page 2 Slot 0 (54.40, 47.00 mm) 원점 불변 유지 및 나머지 20개 빈 슬롯 미출력 확인.
- **사진 배치:** Page 1에 21개, Page 2에 1개의 벡터 배치 래스터 사진(22.40 × 26.30 mm) 정확 검출.
- **글꼴 포함:** Page 1 & Page 2 모두 `NanumGothicExtraBold` 글꼴(2,112,720 바이트)이 임베딩되었으며 대체 문자(`\ufffd`) 없음.
- **100mm 눈금자:** 가로 눈금자(54.4mm ~ 154.4mm, y=185mm) 및 세로 눈금자(47.0mm ~ 147.0mm, x=265mm)가 카드 그리드 외부 마진에 간섭 없이 배치됨.

## 4. 미확정 항목 및 주의사항 기록

1. **이름 영역 7.8mm (실사용 7.4mm) 잠정 조정안 (미승인 상태):**
   - 원문 치수의 단순 합산은 39.2mm로 카드 전체 높이 38.0mm를 초과한다.
   - 본 스파이크에서는 TRD §1.2의 제안에 따라 사진(26.3mm) + 칩(2.9mm) + 상단여백(1.0mm) + 이름영역(7.8mm) = 38.0mm 구조를 적용하였다.
   - 이 조정안은 0.1~0.5mm 미세 보정 범위를 넘는 구조적 변경이므로, 추후 사용자/디자인 검토에서 정식 승인되어야 한다.
2. **실물 인쇄 검증 상태 (Verification Pending):**
   - 본 작업은 독립 PDF 파서(PyMuPDF) 및 브라우저 E2E 검증까지 완료되었으나, 실제 물리 프린터에서 인쇄 후 버니어 캘리퍼스로 측정한 실물 검증은 사용자의 인쇄 환경(하드웨어)에 의존하므로 `verification pending (대기)` 상태를 유지한다.
   - 인쇄 시 주의사항: 반드시 프린터 대화상자에서 **"실제 크기(100%)"**를 선택해야 하며, "용지에 맞춤(Fit to printable area)"이나 기본값으로 자주 적용되는 85% 축소 인쇄를 사용해서는 안 된다.
