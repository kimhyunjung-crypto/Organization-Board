## 1. 개요 및 시험 목적

본 기술 시험(S00.03)은 사진의 EXIF 방향을 안전하게 보정하고, 전용 Web Worker에서 로컬 MediaPipe BlazeFace 검출기를 실행하여 얼굴 기준 자동 크롭(55% 얼굴 높이, 38% 눈높이)과 중앙 cover 크롭, 줌(1~5배) 중심 보존 및 수동 보정 인터랙션이 원본 좌표계 기준 오차 1px 이내로 결정론적으로 동작하는지 검증하는 것을 목적으로 한다.

### 개인정보 및 보안 준수 원칙
- 실제 직원 사진이나 외부 인물 이미지를 일체 사용하거나 수집하지 않았다.
- 모든 시험은 루트가 사전에 생성한 가상 성인 인물 합성 fixture(`tests/fixtures/images/synthetic-portrait.png`) 및 이를 바탕으로 파생 제작한 실제 JPEG EXIF 1~8 방향 fixture만 사용하였다.
- 외부 원격 CDN이나 외부 API 호출에 의존하지 않고 로컬 모델(`/assets/models/blaze_face_short_range.tflite`)과 로컬 WASM·JS 로더(`/assets/mediapipe/wasm/`)만을 자체 호스팅 정적 자원으로 사용하였다 (단, 서비스 워커/캐시 스토리지 기반의 완전 오프라인(PWA) 지원을 의미하는 것은 아님).

## 5. 남은 한계 및 후속 조치 권고사항

1. **합성 인물 단일성 한계 및 16종 독립 회귀와의 구분:**
   - 본 시험에서 `scripts/check-imaging-browser.mjs`를 통한 16종(정방형 8종 + 비정방형 8종) EXIF 기하 및 방향 정규화 회귀 검증은 100% 통과하였다.
   - 그러나 시각적 얼굴 검출에 사용된 기초 fixture(`synthetic-portrait.png`)는 단일 가상 정면 성인 인물(단일 identity)에 국한된다. 따라서 다양한 연령, 성별, 피부톤, 안경, 장신구, 조명 편차, 얼굴 가림 등 다변량 실제 직무 사진 환경에서의 모델 인식률을 완전히 대변할 수 없으며, E03/E04 단계에서 담당자의 실제 샘플 점검이 수반되어야 한다.
2. **ESM 매칭 리졸버 및 개발 서버 정적 라우팅 해결:**
   - Worker 내 MediaPipe 초기화 시 `FilesetResolver.forVisionTasks('/assets/mediapipe/wasm', true)`를 적용하여 모듈형 Worker 환경에 부합하는 ESM JS 로더(`vision_wasm_module_internal.js`)와 WASM 바이너리(`vision_wasm_module_internal.wasm`)가 일치하여 요청되도록 구성하였다.
   - 프로덕션 프리뷰(`vite preview`) 및 정적 빌드 배포 환경에서는 `/public` 자원이 정적으로 서빙되어 정상 동작하나, Vite 8.3 개발 서버(`vite dev`) 환경에서는 Worker 내 동적 `import()` 호출 시 `/* @vite-ignore */` 주석과 무관하게 `?import` 쿼리가 강제 주입되어 `/public` 정적 JS 자원 임포트가 차단(500 에러)되는 문제가 존재하였다.
   - 이를 해결하기 위해 `vite.config.ts`의 `configureServer` 훅에 dev 전용 미들웨어를 배치하여, Vite 내장 transform 미들웨어 진입 전에 허용 목록에 등록된 정확한 3종의 로컬 MediaPipe JS 로더(`/assets/mediapipe/wasm/*.js`) 요청을 가로채 GET/HEAD 메서드로 원본 바이트와 ETag를 무손실 직접 서빙하도록 정적 라우팅을 구성하였다 (안전한 고정 경로 매핑으로 광범위한 파일시스템 접근 및 unsafe-eval 원천 방지).
   - 개발 미들웨어를 통해 로더가 정상 서빙됨에 따라 `face.worker.ts`의 불필요한 `self.import` 몽키패치를 제거하고 표준 ESM 동적 임포트 계약으로 코드를 단순화하였다.
   - 본 구조는 외부 CDN 의존 없이 로컬 서버의 정적 자원으로 구동하는 방식이며, 캐시 스토리지/서비스 워커 기반의 완전 오프라인(PWA) 지원을 의미하지는 않는다.
3. **S00.04 (PDF 및 카드 출력 연계):**
   - 현재 본 Story는 Canvas 출력 및 원본 기준 좌표계 확정까지만 다루며, PDF 생성 및 인쇄 실물 25 × 38mm 검증은 S00.04에서 수행한다.
